## 礼物动作列表装不下时自动上下滚

- `LiveOverview` 里给列表加了个 rAF 循环：滚到底停 0.7 秒 → 往回滚到顶 → 停 → 再往下，如此往复。内容没超出容器就什么都不做。
- 速度按「一遍扫完约 14 秒」换算（`max / 14`），再夹在 8~40px/s：溢出一点点不会慢到像没动，溢出很多也不会快得看不清。
- **最大的坑：Chrome 的 `scrollTop` 是整数**。`scrollTop += 0.13` 写回去会被直接抹掉，列表原地不动 —— 但每帧增量到 0.5px 以上时又会因为四舍五入而「动起来」，所以很容易误判成「逻辑没问题、只是慢」。必须自己维护一个浮点 `position` 累加，最后 `scrollTop = Math.round(position)`。最小复现：`el.scrollTop = 1.093` 读回来是 `1`。
- 另外两处细节：`dt` 钳在 0.064s（标签页切回来时 `now - last` 会很大，一下跳到列表底部）；用户自己滚过就 `Math.abs(scrollTop - position) > 2` 时把 position 同步过去，别硬拽。
- 尊重 `prefers-reduced-motion`：开了就不启动循环。
- effect 依赖用 `giftMotionRows.length` 而不是整个数组 —— 礼物触发动作会改 `characterStates`，跟着它重启会把滚动方向无谓地重置。每帧都重算 `max`，行高变化不需要重启。
- 实测（max=93，8px/s）：轨迹 `11 13 15 … 91 93 93 93 93 91 88 …`，触底停顿约 1s 后反向，实测速度 8.2px/s；不溢出时 `max=0`、`scrollTop` 恒为 0。
- `tsc -b --force` / `vite build` exit 0。

## 礼物动作改成队列，并让它压过说话动作

- 起因：`useLiveServer` 每 400ms 才 flush 一次，一个窗口里可能挤进好几条礼物。旧实现只认 feed 末尾那条 `latestGift`，其余全丢；而且 `activeMotion` 是状态不是队列，就算同时处理也会在同一帧互相覆盖。用户确认走「逐条排队播」的方案。
- 队列三支 effect：
  1. **入队**认 `douyinRoom.feed`：用 `queuedGiftIdRef` 记最大已入队 id，靠 id 单调递增挑出「这一批新来的」。断线重连时 `feed` 会被清零、事件序号从头开始，所以 `feed.length === 0` 时把 `queuedGiftIdRef` 也归零，否则新礼物会被当成旧的丢掉。礼物名走 `normalizeGiftName`（旧代码直接拿原始 `event.gift` 查配置，带空格或全角符号时查不到）。
  2. **出队**认 `giftTick`：没有 `playingGiftRef` 就取一条，`while (next && !giftMotions[next.name]) next = shift()` 跳过没配动作的礼物 —— 否则一条没配的礼物会白占 1.2 秒。
  3. **补漏**认 `characterStates`：播放窗口内 manifest 还没就绪的模型记进 `pendingModelsRef`，等它到位后趁这条礼物还在播补上。
- **播放窗口用 `setTimeout` 推进，绝不能放 effect 的 cleanup**。cleanup 每次依赖变化都会执行，会把「窗口结束」这个信号提前吃掉，队列直接卡死。卸载时另起一个 effect 清定时器。
- 优先级用 `motionHoldUntil` 时间戳（毫秒），不用布尔标志：说话可能持续好几秒，布尔标志没人负责清除，会永久锁死后续所有说话动作。礼物开播时写 `Date.now() + 1200`，`Live2D` 里 `speakingStarted` 触发 `speakMotion` 前比一下。
- **坑**：`applyModelProps` 里 `entry.motionHoldUntil = next.motionHoldUntil` 的赋值在判断之前，所以守卫必须读 `next.motionHoldUntil`，读 `entry` 拿到的是刚被覆盖的新值（正好是反的）。为了不踩这个坑，守卫值在赋值前就算好放进 `giftHolding`。
- 语义选择：窗口内开始说话，说话动作是**丢弃**而不是延后 —— `speakingStarted` 是边沿信号，没有可用的定时器去延后重放。要改成延后得再加一份 pending 状态。

### 验证方式（重要经验）

- **舞台字幕只反映 `activeMotion` 状态，看不到说话动作**：`speakMotion` 是 `Live2D` 内部直接调 `model.motion()`，不经过 React state，所以拿 DOM 观测说话动作永远为空。第一版测试就是这样误判的。
- 说话动作只能在运行时 hook `Live2DModel.prototype.motion` 或加临时探针。本次用后者：在 `speakingStarted` 分支临时 push `{group, blocked}` 到 `window.__motionProbe`，验证完立刻删掉（`grep __motionProbe src/` 确认无残留）。

### 实测结果

- 一次 flush 刷 12 条 → 只播 8 条，第一条是第 5 条的「吹泡泡糖」，确认丢的是最旧的 4 条。

## 添加模型时校验名称唯一

- 模型名称是模型的「身份」：下拉列表、礼物动作配置、说话动作都按名称认模型，重名会分不清。所以 `AddModelModal` 里加了重名检查。
- `AddModelModal` 直接 `useModel()` 读 `modelSources`，不额外收 props —— 和舞台浮层那套「组件自己取数」保持一致。
- 判重前 `trim()` + `toLocaleLowerCase()`：`'Icy'` / `'icy'` / `' icy '` 都算同一个。（`trim()` 会顺带处理全角空格 U+3000，不用单独处理。）
- 三处联动：名称输入框描边转 `$warn`、下方出现「该名称已被使用，请换一个」、「添加模型」按钮禁用。`addPreviewModel` 里再兜一层 `nameTaken` 判断，防止回车之类的路径绕过去。
- **边框色的坑**：`Input` 的 `className` 落在内层 `<input>` 上，所以写在 AddModelModal 里的 `.invalid` 和 `Input` 的 `.input` 都是单类选择器，靠顺序打架。要写成 `input.invalid`（0,1,1 压过 0,1,0）；而且**输入时输入框一直是聚焦的**，`.input:focus`（0,2,0）优先级更高，必须再补 `input.invalid:focus`（0,2,1），否则边焦点上根本看不出重名。
- 顺手修掉一句矛盾文案：预览就绪时会显示「模型加载成功，可以添加」，但重名时按钮是禁用的。改成 `previewStatus === 'ready' && !nameTaken` 才显示。
- 提示用 `<div>` 而不是 `<span>`：`.field > span` 是给字段标签写的（会改颜色和 `margin-bottom`），用 span 就得再跟它打一轮优先级。
- 实测：完全同名 / 小写同名 / 前后空格 三种都出提示、按钮禁用、边框 `rgb(224,171,99)`（聚焦和失焦一致）；改成「鲸鱼娘二号」提示消失、按钮恢复可用、边框回到 `#2d4651`。
- `tsc -b --force` / `vite build` 均 exit 0。

## 舞台背景「固定 / 循环切换」与音乐「单曲循环 / 列表循环」

### 背景

- `BACKGROUND_PRESETS` 从 `StageControlPanel` 挪到 `src/contexts/StageProvider/presets.ts` —— 轮播逻辑在 provider 里，组件和 provider 得共用同一份顺序。同文件放 `BACKGROUND_CYCLE_INTERVAL_MS = 12_000`。
- 轮播用 `setTimeout` 而不是 `setInterval`，依赖里带 `backgroundUrl`：每换一张就重新计时，所以手动点预设也会把计时器重置，不会出现「刚点完就被轮播换走」。
- 当前背景是自定义图（不在预设里）时 `findIndex` 返回 -1，`(-1+1)%5 === 0` 正好从第一张开始轮，不用额外分支。
- `resetStage` 里补 `setBackgroundMode('fixed')`。

### 音乐

- 原来 `audio.loop` 写死 `true`，等于永远单曲循环。现在按模式给：`single` → `loop = true`（`ended` 不触发），`list` → `loop = false`，靠 `ended` 接下一首。
- **播放中切换模式要单独同步 `audio.loop`**：audio 元素只在换音源时重建，改 state 不会改它。加了一支 `useEffect(..., [loopMode])` 补上。
- `ended` 里要调 `startSource` 起下一首，但 `startSource` 是 `useCallback`，不能在函数体里引用自己。用 `startSourceRef` 中转（和文件里 `volumeRef.current = volume` 同一个套路，render 期间赋值）。
- 自定义音源（URL / 本地文件）`presetId` 是空串，在预设列表里查不到「下一首」，退回重播当前这首 —— 直接跳到第一首预设会很突兀。
- `reset` 里补 `setLoopMode('single')`。

### UI

- 两处都用 `<Segmented block />`（默认 xs = 30px），标签在上、控件撑满一行，和 `VoiceSetting` 里的 `.behaviorRow` 同一套排版。新增 `.modeRow` 样式。
- 位置：背景那个放在「无背景 / 本地图片」之后，音乐那个放在音量滑块之后。
- 实测两个控件都是 259×30，`scrollWidth === clientWidth`，两个选项文字没被挤。

### 验证

- 默认值：固定 / 单曲循环。
- 背景：切到循环 12s 后 `background.png → bg_cinematic.png`；手点赛博后 3s 仍在 `bg_cyberpunk.png`（计时器重置）；切回固定 13s 不动。
- 音乐：单曲循环时 `audio.loop === true`；切列表循环后变 `false`，把 `currentTime` 拖到结尾 → 自动接 `music-02-cyberpunk.wav`；切回单曲后同样操作仍停在 02。Audio 实例总数 2（初始 + 下一首各一个）。
- 重置舞台：循环切换 / 列表循环 → 固定 / 单曲循环。

## 礼物动作卡片过滤掉隐藏 / 已删除的模型

- 现象：`GiftMotionCard` 里列出了「fastly.jsdelivr.net · Tap」这类条目，但那个模型在舞台上是隐藏的。
- 根因：`rows` 直接 `modelSources.map(...)`，没看 `characterStates[id].modelVisible`。
- 改法：`.filter((source) => characterStates[source.id]?.modelVisible !== false)`，和 `AiChatProvider` 里「轮流挑说话角色」用的是同一套判断（`!== false` 而不是 `=== true`，这样模型还没加载、state 还没建出来时仍然算可见）。
- **已删除的模型本来就不会出现**：`deleteModel` 会同时从 `modelSources` 和 `characterStates` 里删，而 `giftMotionTargets` 是遍历 `modelSources` 生成的，遗留的 `giftMotions` 配置键不会被渲染。实测删除后卡片从 2 种降到 1 种，刷新后 `localStorage['ailive.online-models']` 是 `[]`，确实没残留。
- 一个模型被隐藏后，如果某个礼物只配了它，那一行会整条消失（`targets.length === 0` 的既有过滤）；所有模型都隐藏时整块卡片不渲染。
- **测试踩坑**：用 `addInitScript` 写 localStorage 种子时，`page.reload()` 会再跑一次并覆盖掉删除结果，看起来像「删除不生效」。要加 `sessionStorage` 标记只注入一次。
- 实测：隐藏线上模型后卡片从「2 种 / 樱花(两模型) + 大啤酒」变成「1 种 / 樱花(仅 DS 鲸鱼娘)」；重新显示后恢复成 2 种。
