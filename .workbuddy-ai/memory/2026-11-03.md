## Live2D 渲染重构：多 canvas → 单一 SharedStage

- 背景：舞台上每个模型都用 `Live2DCanvas` 各自创建一个 PIXI Application，DOM 里出现多个 `.model-layer > .live2d-stage > canvas`。
- 方案：新增 `src/components/SharedStage.tsx`，全舞台共用一个 `PIXI.Application`（一张 canvas），所有 `Live2DModel` 作为 `app.stage` 子节点，靠 `zIndex`（`sortableChildren`）决定前后层级；命中检测/拖拽/眼神聚焦都在 SharedStage 内部完成，通过 `onActivateModel` 回传激活模型。
- `App.tsx` 用 `stageModels` memo 计算每个模型的渲染参数（motion / expressions / size / positionResetKey / zIndex / speechText），删除了 `modelRefs`、`handleStagePointer*` 和 `.model-interaction-layer`。
- `AddModelModal` 不再内嵌 Live2D 预览（否则会多一张 canvas），改为拉取 model3.json 校验 `FileReferences.Moc/Textures`（Cubism 2 校验 `model/textures`），展示配置摘要后再允许添加。
- 关键坑：StrictMode 双挂载时，旧实例销毁若带 `texture/baseTexture` 会销毁 PIXI 贴图缓存，导致新实例渲染成黑色剪影。销毁模型和 app 时只传 `{ children: true }`，贴图交给 PIXI 缓存/GC 管理。
- CSS：`.live2d-stage` / `.model-layer` / `.model-interaction-layer` 全部替换为 `.shared-stage`(+`-canvas`)，`.preview-caption` 加 `pointer-events:none` 避免挡住拖拽，`.speech-bubble` 用 `translate(-50%,-100%)` 定位在模型头顶。
- 现状：DOM 里 Live2D 只剩一张 canvas；粒子层仍是 particles.js 自己的 canvas（`.stage-atmosphere`），若要「整页只有一张 canvas」需把粒子并进 PIXI。

### 滑块悬停：未填充段渐入高光

- 需求：鼠标移入滑块条时加一点背景渐变。
- 做法：轨道 `background-image` 分两层——下层是已填充段（`$accent` 到填充点），上层是「从填充点开始、到右端渐隐为透明」的高光层，颜色 `rgb($accent / calc(var(--slider-sheen) * 0.34))`。
- 关键：**渐变本身不能被 transition 插值**，所以把透明度抽成自定义属性 `--slider-sheen`（0→1），再用 `@property { syntax:'<number>'; inherits:true }` 注册它，`transition: --slider-sheen .16s ease` 才能真的过渡；伪元素 `::-webkit-slider-runnable-track` 通过继承拿到父元素正在过渡的值。没注册的普通自定义属性只能硬切。
- Sass 坑：`rgb(#{$rgb} / calc(...))` 会被当成 Sass 内置 `rgb()` 求值并报 `Missing element $green`。必须整串 `unquote('rgb(...)')` 变成裸 CSS 字符串再塞进 gradient。
- 触发范围：`:hover:not(:disabled)` 挂在 `.input` 上（14px 高的轨道带），禁用态不响应。
- 实测（2 倍截图逐像素）：60% 时未填充段从 `53,74,85` → `69,122,120`（贴 thumb 处）单调渐隐到 `54,77,87`；90% 时那截很短但仍可见（→ `68,118,116`）；70ms 抓帧确认是渐变过程而非硬切。

### 加载提示合并：多模型只显示一条「正在加载模型」
