## 气泡跟随模型大小缩放 + 位置上移

- 气泡是 DOM 元素、模型是 PIXI canvas，两者尺寸无关。做法：`updateBubbles` 里算 `bubbleScale = clamp(模型渲染高度 / (舞台高度 * 0.43), 0.7, 1.45)`，写进元素上的 `--bubble-scale`；SCSS 里字号/内边距/圆角/最大宽度/尾巴尺寸全部用 `calc(基准px * var(--bubble-scale))` 换算，等比且文字仍按新字号重新排版（比 `transform: scale()` 清晰）。
- 基准 0.43 是实测值：默认大小 0.6 时模型渲染高度约占舞台高度 43%，这样默认大小的气泡保持原来的 11px 字号（实测 scale=0.999、font=10.99px），只是上下缩放。
- 夹紧 0.7~1.45：0.2 时字号 7.7px（再小不可读），0.95 时 15.95px（再大盖住舞台）。
- 位置：`top` 从 `bounds.y + height * 0.06` 改成 `bounds.y + height * 0.03`，按模型高度等比上移（默认大小约 10px）。
- 踩坑一：一开始把 `top` 直接放在包围盒顶边再加 CSS 上提，结果鲸鱼娘模型浮起 50px+——Live2D 的 `getBounds()` 顶部含大片透明边距（这个模型约占高度 20%），不同模型差异很大，只能用「按比例的小偏移」这种折中值。
- 踩坑二：`--bubble-scale` 做了「值没变就不重写」的防抖（每 4 帧写一次会触发文字重排），但气泡卸载时忘了清缓存，导致第二次说话时新元素沿用旧判断、跳过写入而停在默认 scale=1。在 ref 回调的 else 分支补 `bubbleScalesRef.current.delete(id)`。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 实测 0.6/0.2/0.95 三档 scale = 0.999 / 0.700 / 1.450，说话→结束卸载→再说话后 scale 仍为 1.450，无 pageerror。
- 遗留：气泡 `z-index: 5` 在 `.live2d`（z-index 3）的层叠上下文里，永远压在 LiveOverview 卡片（z-index 8）下面；气泡上移后更容易被卡片挡住。验证时用「隐藏卡片」规避。

## 修 bug：首次进入点「播放」无反应

- 现象：刚打开页面点舞台控制台的「播放」按钮，音乐不响，卡片仍停在「已暂停 / 0:00 / --:--」，无任何报错。
- 根因：`MusicProvider` 的 `toggle()` 开头是 `const audio = audioRef.current; if (!audio) return`。而 `Audio` 元素只在 `startSource()` 里创建，首次进入时没有任何人调用过它，`audioRef.current` 为 null，于是整个函数静默返回。按钮的 `disabled={!track.url}` 又因为 `track.url` 有默认值（`MUSIC_PRESETS[0].url`）而是可点的，所以表现为「点了没反应」。
- 同批验证的另外两个入口都正常：▶ 按钮走 `playUrl`（探测元数据后 `startSource`），预设 chip 走 `selectPreset`，两者都会创建 audio 元素。
- 修法：`toggle()` 在没有 audio 元素时，用当前曲目起一个 —— `startSource(track.url, track.name, presetId, true)`，依赖改成 `[startSource, track.url, track.name, presetId]`。
- 顺带覆盖 `reset()` 之后的状态：`reset()` 会把 `audioRef.current` 置 null，修好后「重置舞台 → 点播放」也能正常起来。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 用真实点击（不传 `--autoplay-policy` 标志）复现原 bug 后再验修复；完整循环「播放 → 暂停 → 再播放 → 切雨声 → 暂停 → 重置舞台 → 再播放」每步状态、呼吸动画、`--level` 都正确，无 pageerror。
- 备注：`new Audio()` 元素不挂在 DOM 上，所以 `document.querySelectorAll('audio').length` 恒为 0，不能拿它判断有没有在播。

## 禁止配置弹窗的浏览器自动填充

- 现象：AI 配置弹窗的 API Key 输入框被 Chrome 当成登录密码框，自动填入已保存凭据，背景被刷成浅蓝（`#e8f0fe`）、文字变黑，和暗色主题完全割裂。
- 根因：`type="password"` + 没有 `name`/`autocomplete` 提示，Chrome 靠字段类型猜成登录表单。密码框上的 `autocomplete="off"` 会被 Chrome 无视。
- 三层处理：
  1. `Input` / `Textarea` 组件默认 `autoComplete="off"`（可被调用方覆盖）——对普通文本/URL 字段足够，Chrome 就不会弹表单历史建议。
  2. 两个 Key 字段（`AiConfigModal`、`TtsConfigModal`）改用 `autoComplete="new-password"` + 非标准 `name`（`doubao-ark-key` / `volcengine-tts-key`）+ `data-1p-ignore` / `data-lpignore="true"` + `spellCheck={false}` / `autoCapitalize="off"`。`new-password` 让 Chrome 认为这是「设置新密码」而不是「已有凭据」，这是挡住密码管理器填充的标准手段。
  3. 兜底：新增 `@mixin autofill-reset($surface, $color)`（`styles/mixins.scss`），`&:-webkit-autofill` 三态用 `box-shadow: 0 0 0 1000px <surface> inset` 盖住底色 + `-webkit-text-fill-color` 统一文字色。**Chrome 的 autofill 背景色无法用 `background` 覆盖**（内部 `!important`），只能用足够大的内阴影。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 实测 AI 弹窗字段 `name=doubao-ark-key / autocomplete=new-password / data-1p-ignore / data-lpignore=true`，其余字段 `autocomplete=off`；TTS 弹窗 `name=volcengine-tts-key / new-password`；`document.styleSheets` 里两条 autofill 规则存在且 `box-shadow: rgb(16,27,36) 0 0 0 1000px inset`；生产产物 `dist/assets/index-*.css` 中同样存在。
- 注：`data-*` 连字符属性在 JSX 里不受 TS 类型检查限制，可以直接写。

## 弹窗布局重构 + 统一滚动条样式

- 现象：AI 配置弹窗里回复一多，底部「取消 / 保存设置」被内容顶出面板外（截图里按钮悬在弹窗下沿之外）；「最近回复」列表用的是浏览器原生浅灰粗滚动条，和暗色主题割裂。

- **动画是这活儿的难点**，踩了三个坑：
  1. **面板不能是遮罩的子节点**。第一版 `<div class="backdrop"><section class="panel">`，遮罩用 `opacity 0→1` 淡入，子元素会继承父级的 opacity —— 开场几帧整个抽屉是半透明的，根本看不出"滑进来"，只像"淡出来"。改成 `root(固定定位, 不做透明度) > [backdrop, panel]` 兄弟结构，面板 `opacity` 恒为 1，只有遮罩淡入。
  2. **刚挂载的元素不会过渡**。首帧直接渲染成归位态，浏览器没有起点可插值。第一版用 double `requestAnimationFrame`，但本机跑 Live2D+PIXI（swiftshader）只有 ~17fps，两帧就是 130ms，点开明显卡一下。改成 `useLayoutEffect` 里 `void panel.offsetWidth` 强制样式结算 —— 同步完成，不受帧率影响，实测首帧（15ms）就已经在过渡了。
  3. **退出不能用固定定时器卸载**。原来 `setTimeout(unmount, 240)`，但重负载下过渡要晚 2 帧才开始、实际要跑 220ms，结果抽屉只滑出 36% 就被卸载，看起来像"直接消失"。改成监听面板的 `onTransitionEnd`（判 `propertyName === 'transform'` + `event.target === event.currentTarget` + `!open`），另留 `EXIT_FALLBACK_MS = 700` 兜底（过渡被打断/合并时用）。
- 进出用不同的时长和曲线：`transition` 取的是**目标态**那条规则 —— `.panel` 上是关闭用的 220ms `cubic-bezier(0.4,0,1,1)`（快走），`.visible .panel` 上是打开用的 320ms `cubic-bezier(0.22,1,0.36,1)`（缓出）。这样一开一关节奏不对称，符合直觉。
- `.visible .panel` 和 `.panel.left` 都是 (0,2,0)，靠源码顺序决定胜负，所以 `.panel { &.left {} }` 必须写在 `.visible .panel` 前面。
- 交互补齐：Esc 关闭、点遮罩空白处关闭（`onMouseDown` 挂在空的 backdrop div 上，面板是兄弟节点不会被误伤，从面板里拖到遮罩松开也不会误关）、`prefers-reduced-motion` 降到 1ms。
- `AiConfigModal` 目录 `git mv` 成 `AiConfigDrawer`，组件改名 `AiConfigDrawer`，内部 `<Modal>` 换 `<Drawer>`；去掉 `if (!open) return null`（卸载交给 Drawer 管，否则没有退出动画），`maxHeight` prop 也不需要了。`TopBar` 只改了 import 和标签名。

## 抽屉默认宽 600px；最近回复列表改成「吃掉剩余高度」

- `$drawer-width: min(600px, 100vw)`（460 → 600）。600 下 API Key 输入框 511px、单价框 271px。
- 回复列表原来是写死的 `max-height: 180px`。直接调大数值会撑破 body，变成「body 一根滚动条 + 列表一根滚动条」两条并排 —— 所以改成按剩余空间自适应：
  - `AiConfigDrawer` 的 children 外面包一层 `.content { display: flex; flex-direction: column; min-height: 100% }`。用 `min-height` 而不是 `height`：内容超高时自己长高、交给 body 滚，子项也不会被 flex 压扁。
  - `.history { flex: 1 1 0; min-height: 160px; display: flex; flex-direction: column }`。
  - `.history ul { flex: 1 1 0; min-height: 0; overflow-y: auto }`，不再写 max-height。
  - **关键：`flex-basis` 必须是 `0` 不是 `auto`**。用 `auto` 时列表的内容高度会算进 `.content` 的 auto 高度，`.content` 被撑高 → body 滚而不是列表滚；用 `0` 时 `.content` 高度只由表单决定，剩余空间全给列表。
- 实测（窗口高度 → 列表可视高度）：800→140（此时 body 也滚，表单本身已快占满）、900→206、950→256、1000→306、1080→386、1200→506、1440→746。950 及以下 body 不再滚，只有列表自己一根滚动条。
