## 气泡跟随模型大小缩放 + 位置上移

- 气泡是 DOM 元素、模型是 PIXI canvas，两者尺寸无关。做法：`updateBubbles` 里算 `bubbleScale = clamp(模型渲染高度 / (舞台高度 * 0.43), 0.7, 1.45)`，写进元素上的 `--bubble-scale`；SCSS 里字号/内边距/圆角/最大宽度/尾巴尺寸全部用 `calc(基准px * var(--bubble-scale))` 换算，等比且文字仍按新字号重新排版（比 `transform: scale()` 清晰）。
- 基准 0.43 是实测值：默认大小 0.6 时模型渲染高度约占舞台高度 43%，这样默认大小的气泡保持原来的 11px 字号（实测 scale=0.999、font=10.99px），只是上下缩放。
- 夹紧 0.7~1.45：0.2 时字号 7.7px（再小不可读），0.95 时 15.95px（再大盖住舞台）。
- 位置：`top` 从 `bounds.y + height * 0.06` 改成 `bounds.y + height * 0.03`，按模型高度等比上移（默认大小约 10px）。
- 踩坑一：一开始把 `top` 直接放在包围盒顶边再加 CSS 上提，结果鲸鱼娘模型浮起 50px+——Live2D 的 `getBounds()` 顶部含大片透明边距（这个模型约占高度 20%），不同模型差异很大，只能用「按比例的小偏移」这种折中值。
- 踩坑二：`--bubble-scale` 做了「值没变就不重写」的防抖（每 4 帧写一次会触发文字重排），但气泡卸载时忘了清缓存，导致第二次说话时新元素沿用旧判断、跳过写入而停在默认 scale=1。在 ref 回调的 else 分支补 `bubbleScalesRef.current.delete(id)`。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 实测 0.6/0.2/0.95 三档 scale = 0.999 / 0.700 / 1.450，说话→结束卸载→再说话后 scale 仍为 1.450，无 pageerror。
- 遗留：气泡 `z-index: 5` 在 `.live2d`（z-index 3）的层叠上下文里，永远压在 LiveOverview 卡片（z-index 8）下面；气泡上移后更容易被卡片挡住。验证时用「隐藏卡片」规避。

## 背景音乐状态提升 + 独立播放卡片

- 背景：音乐播放全部写在 `StageControlPanel` 的局部 state 里（`<audio>` 元素、`musicUrl`/`musicName`/`musicError`、音量 effect），而「正在播放」条在 `LiveOverview` 里，两边够不着。必须把播放状态提升。
- 新增 `src/contexts/MusicProvider/`（`MusicContext.ts` + `presets.ts` + `index.tsx`），Provider 挂在 `VoiceProvider` 内层。上下文值：`track` / `presetId` / `isPlaying` / `currentTime` / `duration` / `volume` / `error` / `analyser` + `selectPreset` / `playUrl` / `playFile` / `toggle` / `setVolume` / `clearError` / `reset`。
- 换音源必须新建 `Audio` 元素：`createMediaElementSource` 一旦绑定就无法解绑，只有换元素才能让后来的跨域音源不被静音。`startSource()` 统一负责建元素、绑事件、接 Web Audio。
- 跨域降级：`isAnalysable(url)` 判断同源/blob/data 才接 `AnalyserNode`（`fftSize=512`、`smoothingTimeConstant=0.72`），否则 `analyser=null`，卡片退回 CSS 固定节奏动画。
- `timeupdate` 约 4Hz，只在 `Math.floor` 变化时才写 state，避免每秒 4 次无谓重渲染。
- 新增 `src/components/NowPlayingCard/`：`Card padding="none"` 外壳 + 左侧呼吸圆环 + 中间曲目信息 + 右侧 4 根律动条。只负责展示，状态全靠 props。
- 呼吸动画：`.playing .orb { animation: breathe 2.6s }`，只动 `box-shadow`（0 0 10px/1px ↔ 0 0 22px/6px）。
- 律动条用 `transform: scaleY()` + `transform-origin: bottom`（比改 height 便宜），由 `--level` 驱动，`scaleY(0.18 + level * 0.82)`。
- **频谱调参踩了 4 轮**（本次最费时）：
  1. `fftSize=64`（32 bin）+ 线性切 4 段 → 前三段全在 4.5kHz 以下，第一根顶满后两根不动（实测高度 `[28,19,5,5]`）。改对数切分（60Hz~12kHz 倍频程均分）+ `fftSize=512`。
  2. 用「近期峰值」做归一化 → 四根全顶满（`[28,28,28,14]`）；换「慢速平均 × 1.7」→ 前两根几乎不动（`[20,22,28,9]`）。
  3. 根因是取频段内**最大 bin**，低频那个 bin 长期饱和在 255。改成取**频段均值**。
  4. 「自适应对比度拉伸（low/high 收敛）」→ 前两根常年 0.96~1.00。最终：慢速平均（0.98/0.02，时间常数约 0.8s）做基准，`level = clamp((ratio - 0.55) / 0.75, 0.12, 1)`。实测三首曲子都有明显动态。
- 暂停态修视觉 bug：电平归零后 `scaleY(0.18)` 把 28px 的条压成 5px，四根条看起来像四个小方块。改为 `.card:not(.playing) .bar` 用一组静态 `--rest`（0.3/0.6/0.45/0.22）+ `opacity: 0.5`，读起来才是「已暂停」。播放时 `--level` 逐帧写入，`.playing .bar` 要关掉 transform 过渡，否则每帧重启补间会发飘。
- 顺带清理：`LiveOverview/types.ts` 删掉 `LiveNowPlaying` 与 `nowPlaying` 字段，`LiveDataProvider` 删掉那行假数据；`StageControlPanel` 删掉 `playAudioSource` / `getMusicDisplayName` / `handleMusicUrl` / `selectMusicPreset` / `toggleMusic` / `audioRef` / `musicObjectUrlRef` / 3 个 state / `<audio>` 元素 / 音量 effect，改为 `useMusic()` 消费。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 实测初始「已暂停/轻柔/0:00 / --:--」→ 点「赛博」变「正在播放/0:01 / 0:35」且 1.2s 后走秒 → 暂停回「已暂停」且 `orbAnim: none` → 切「轻柔」变「0:01 / 0:40」；`--level` 三首曲子动态区间正常；连拍 4 帧确认条形高度逐帧变化；概览三列底边严格对齐（全部 411px）；圆环内点偏移 (0,0)。
