## 气泡跟随模型大小缩放 + 位置上移

- 气泡是 DOM 元素、模型是 PIXI canvas，两者尺寸无关。做法：`updateBubbles` 里算 `bubbleScale = clamp(模型渲染高度 / (舞台高度 * 0.43), 0.7, 1.45)`，写进元素上的 `--bubble-scale`；SCSS 里字号/内边距/圆角/最大宽度/尾巴尺寸全部用 `calc(基准px * var(--bubble-scale))` 换算，等比且文字仍按新字号重新排版（比 `transform: scale()` 清晰）。
- 基准 0.43 是实测值：默认大小 0.6 时模型渲染高度约占舞台高度 43%，这样默认大小的气泡保持原来的 11px 字号（实测 scale=0.999、font=10.99px），只是上下缩放。
- 夹紧 0.7~1.45：0.2 时字号 7.7px（再小不可读），0.95 时 15.95px（再大盖住舞台）。
- 位置：`top` 从 `bounds.y + height * 0.06` 改成 `bounds.y + height * 0.03`，按模型高度等比上移（默认大小约 10px）。
- 踩坑一：一开始把 `top` 直接放在包围盒顶边再加 CSS 上提，结果鲸鱼娘模型浮起 50px+——Live2D 的 `getBounds()` 顶部含大片透明边距（这个模型约占高度 20%），不同模型差异很大，只能用「按比例的小偏移」这种折中值。
- 踩坑二：`--bubble-scale` 做了「值没变就不重写」的防抖（每 4 帧写一次会触发文字重排），但气泡卸载时忘了清缓存，导致第二次说话时新元素沿用旧判断、跳过写入而停在默认 scale=1。在 ref 回调的 else 分支补 `bubbleScalesRef.current.delete(id)`。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 实测 0.6/0.2/0.95 三档 scale = 0.999 / 0.700 / 1.450，说话→结束卸载→再说话后 scale 仍为 1.450，无 pageerror。
- 遗留：气泡 `z-index: 5` 在 `.live2d`（z-index 3）的层叠上下文里，永远压在 LiveOverview 卡片（z-index 8）下面；气泡上移后更容易被卡片挡住。验证时用「隐藏卡片」规避。

## 修 bug：首次进入点「播放」无反应

- 现象：刚打开页面点舞台控制台的「播放」按钮，音乐不响，卡片仍停在「已暂停 / 0:00 / --:--」，无任何报错。
- 根因：`MusicProvider` 的 `toggle()` 开头是 `const audio = audioRef.current; if (!audio) return`。而 `Audio` 元素只在 `startSource()` 里创建，首次进入时没有任何人调用过它，`audioRef.current` 为 null，于是整个函数静默返回。按钮的 `disabled={!track.url}` 又因为 `track.url` 有默认值（`MUSIC_PRESETS[0].url`）而是可点的，所以表现为「点了没反应」。
- 同批验证的另外两个入口都正常：▶ 按钮走 `playUrl`（探测元数据后 `startSource`），预设 chip 走 `selectPreset`，两者都会创建 audio 元素。
- 修法：`toggle()` 在没有 audio 元素时，用当前曲目起一个 —— `startSource(track.url, track.name, presetId, true)`，依赖改成 `[startSource, track.url, track.name, presetId]`。
- 顺带覆盖 `reset()` 之后的状态：`reset()` 会把 `audioRef.current` 置 null，修好后「重置舞台 → 点播放」也能正常起来。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 用真实点击（不传 `--autoplay-policy` 标志）复现原 bug 后再验修复；完整循环「播放 → 暂停 → 再播放 → 切雨声 → 暂停 → 重置舞台 → 再播放」每步状态、呼吸动画、`--level` 都正确，无 pageerror。
- 备注：`new Audio()` 元素不挂在 DOM 上，所以 `document.querySelectorAll('audio').length` 恒为 0，不能拿它判断有没有在播。

## 禁止配置弹窗的浏览器自动填充

- 现象：AI 配置弹窗的 API Key 输入框被 Chrome 当成登录密码框，自动填入已保存凭据，背景被刷成浅蓝（`#e8f0fe`）、文字变黑，和暗色主题完全割裂。
- 根因：`type="password"` + 没有 `name`/`autocomplete` 提示，Chrome 靠字段类型猜成登录表单。密码框上的 `autocomplete="off"` 会被 Chrome 无视。
- 三层处理：
  1. `Input` / `Textarea` 组件默认 `autoComplete="off"`（可被调用方覆盖）——对普通文本/URL 字段足够，Chrome 就不会弹表单历史建议。
  2. 两个 Key 字段（`AiConfigModal`、`TtsConfigModal`）改用 `autoComplete="new-password"` + 非标准 `name`（`doubao-ark-key` / `volcengine-tts-key`）+ `data-1p-ignore` / `data-lpignore="true"` + `spellCheck={false}` / `autoCapitalize="off"`。`new-password` 让 Chrome 认为这是「设置新密码」而不是「已有凭据」，这是挡住密码管理器填充的标准手段。
  3. 兜底：新增 `@mixin autofill-reset($surface, $color)`（`styles/mixins.scss`），`&:-webkit-autofill` 三态用 `box-shadow: 0 0 0 1000px <surface> inset` 盖住底色 + `-webkit-text-fill-color` 统一文字色。**Chrome 的 autofill 背景色无法用 `background` 覆盖**（内部 `!important`），只能用足够大的内阴影。
- 校验：`tsc -b --force` / `vite build` exit 0；Playwright 实测 AI 弹窗字段 `name=doubao-ark-key / autocomplete=new-password / data-1p-ignore / data-lpignore=true`，其余字段 `autocomplete=off`；TTS 弹窗 `name=volcengine-tts-key / new-password`；`document.styleSheets` 里两条 autofill 规则存在且 `box-shadow: rgb(16,27,36) 0 0 0 1000px inset`；生产产物 `dist/assets/index-*.css` 中同样存在。
- 注：`data-*` 连字符属性在 JSX 里不受 TS 类型检查限制，可以直接写。

## 弹窗布局重构 + 统一滚动条样式

- 现象：AI 配置弹窗里回复一多，底部「取消 / 保存设置」被内容顶出面板外（截图里按钮悬在弹窗下沿之外）；「最近回复」列表用的是浏览器原生浅灰粗滚动条，和暗色主题割裂。
- 根因一：`Modal` 的 `.panel` 只有 `max-height` 没有 `overflow`，`scrollable={false}` 时内容直接溢出面板（`overflow: visible`），把 `.actions` 挤出可视区。
- 根因二：`scroll-thin` mixin 只写了标准属性 `scrollbar-width/color`，而 `.history ul` **根本没 include 它**，所以吃的是原生滚动条。
- Modal 结构改造（`components/Modal/index.tsx` + `.scss`）：panel 变 `display: flex; flex-direction: column`，children 包进新的 `.body`（`flex: 1; min-height: 0`），header / actions 都加 `flex: 0 0 auto`。`.scrollable` 从 panel 自身滚动改为 `.scrollable .body { overflow-y: auto }`。这样标题和按钮永远固定，只有内容区滚。
- `scroll-thin` 重写（`styles/mixins.scss`）：**只用 `::-webkit-scrollbar` 系列**（6px、thumb 圆角 999px、`#4a6a78`、hover `#5d8492`、track/corner 透明）。关键坑：一旦写了 `scrollbar-color` / `scrollbar-width`（非 auto），Chrome 121+ 会**忽略 `::-webkit-scrollbar` 的圆角与 hover**，只能得到方块 thumb —— 两者不能共存。
- `.history ul` 补上 `@include scroll-thin`；同时全仓核对 `overflow-y: auto` 的 5 处（Modal body / AiConfigModal 列表 / ModelControlPanel / ScrollArea / StageControlPanel）都已带 mixin。
- AiConfigModal 去掉 `scrollable={false}`（它没有下拉框，可安全滚动），并单独设 `maxHeight="min(780px, calc(100vh - 40px))"`：常规内容约 720px，给到 780px 后 body 不再滚动，只剩列表内部一条滚动条，避免两条并排。
- 校验：`tsc -b --force` / `vite build` exit 0。Playwright 实测（mock EventSource + ark + TTS 攒出 5 条真实回复）：panel 780 高、`actions.bottom 834 <= panel.bottom` → 按钮在面板内；`body.scrollHeight === clientHeight` 不滚动；`list 180 / scrollHeight 262` 内部滚动；`::-webkit-scrollbar` 计算值 `width 6px / thumb rgb(74,106,120) / radius 999px`。矮视口 560 下 body 滚动（379>347）而按钮仍 `inside: true`。TTS 弹窗（scrollable=false）与添加模型弹窗（默认）回归正常。
- 环境注：本机 Chrome 是 Windows 11 的 overlay 滚动条（`offsetWidth - clientWidth === 0`，平时自动隐藏），所以静态截图看不到滚动条；样式规则本身已验证生效，用户若关闭系统「自动隐藏滚动条」即为常驻的 6px 深灰圆角条。
- 附带发现：`Modal` 没有监听 Escape 关闭，Playwright 里 `keyboard.press('Escape')` 关不掉弹窗，只能点 `aria-label="关闭"` 或点遮罩。

## 密码框统一加「眼睛」切换可见性

- 在 `Input` 组件层做，而不是逐个弹窗改：只要 `type === 'password'` 就自动渲染眼睛按钮，以后新增的密码框自动获得。
- `variant === 'bare'` 时不做（这类输入框嵌在自定义外壳里，位置由调用方决定）。
- 实现（`components/Input/index.tsx`）：组件内 `useState(revealed)`，input 外层包 `<span class="wrap">`（`position: relative`），按钮绝对定位在右侧。切换时把 `type` 在 `password` / `text` 之间改，而不是用 `-webkit-text-security`（后者只有 Blink 支持，非 WebKit 会明文泄露）。
- 关键细节：按钮 `onMouseDown` 里 `preventDefault()`，否则点击会抢走输入框焦点，光标跳回末尾、输入法被打断。实测点击后 `document.activeElement` 仍是 input。
- 图标内联 SVG（项目没有图标库）：睁眼 = 当前掩码（点了能看见），睁眼 + 斜线 = 当前明文（点了会藏起来）。
- 样式（`index.module.scss`）：`.affixed { padding-right: 32px }` **必须排在 `.lg` 之后**，否则被 `.lg` 的 `padding: 0 10px` 简写盖掉；`.reveal` 24×24、`right: 5px`、`translateY(-50%)`、`color: $text-faint`、hover 加 `#ffffff0f` 底、`focus-visible` 描边。
- 无障碍：`aria-label`（显示密码 / 隐藏密码）+ `aria-pressed`，`type="button"` 避免在表单里当提交按钮。
- 校验：`tsc -b --force` / `vite build` exit 0。Playwright 实测两个弹窗：密码框 `hasEye=true`、`paddingRight 32px`、按钮完全落在输入框内且垂直居中（误差 <1px）；点击后 `type: password → text → password`，`aria-label` 与 `aria-pressed` 同步，值正确显示，焦点不丢；非密码框（接口地址 / 模型 ID）无按钮、`paddingRight 10px`。

## 收支面板接真实计算 + 直播配置弹窗

- 需求：删「今日获票」行；AI 配置加模型单价（元/百万 tokens）；顶栏加「直播配置」按钮，把房间号输入/连接移进去；礼物单价可配，收入 = 礼物件数 × 单价，利润 = 收入 - 模型花费。
- **礼物件数**：原来 `stats.gift` 是**事件条数**（一次连击算 1），加了 `stats.giftCount`，在 gift case 里 `+= event.count || 1`。算收入必须用件数。
- **token 记账**：`createDoubaoChatReply` 改为返回 `{ text, usage }`（取响应体 `usage.prompt_tokens / completion_tokens / total_tokens`）；`AiChatProvider` 累计到 `usage: AiChatUsage { promptTokens, completionTokens, totalTokens, calls }`。**记账放在回复去重之前** —— 即使这条因为复读被丢掉，token 也真花了。
- **单价**：`AiChatSettings` 加 `inputPrice` / `outputPrice`，默认 0.8 / 2（方舟 Doubao-Seed-Character 公开价），`readPrice()` 校验非负有限数；AiConfigModal 里两个 number input 并排（`.prices` grid 1fr 1fr），单位跟在 label 后（`> span em`）。
