## 节流参数：写清影响范围 + 复位

`AiConfigDrawer` 的「节流参数」块（昨天刚做成可调）补了两件事。

  原来光看「回复间隔 / 同一观众冷却 / 重复内容窗口」这三个名字，没人知道谁管全局、谁只管弹幕。

  `全直播间 · 不分是谁发的，同一句话（忽略空格标点）在窗口内只答一次`。
- **冷却的起点是「进队列」，不是「被回复」**（`enqueue` 里 `pushQueue` 之后才 `cooldowns.set`），

  回复本身要花几百毫秒，下一个 tick 时 `sinceReply` 只有 700 多，够不到 1000，于是**实际是两拍一条 ≈ 1.7s/条**，
  不是 1s。推送比这快就会堆到 `MAX_QUEUE = 10` 然后开始挤掉最早的非礼物事件（55 条只答了 42 条）。
  改成 2.0s 一条推送、等 122s，才稳定拿到 55 次调用。**要跑长序列测试，先按 1.7s/条估时间，别按配置的 1s 估。**
- `tsc -b --force` exit 0，`vite build` 5.62s（975.85 kB）。

## 断开时不打断最后一句

- 用户追加要求：「断开后 不要直接打断说话，让把最后一条回复说完再结束」。
  于是把上一轮加进 `!liveConnected` effect 里的 `stopSpeaking()` **去掉**（`useVoice()` 也退回只解构
  `speak` / `voices`），队列照旧清空、`pendingCount` 归零。
- 边界划在「已经在说的」和「还没开口的」之间：**正在播放的那一句让它自然说完**（`speak` 在
  `onended`/`onerror` 时才 resolve，说完才写回复记录），**请求还在路上的那一条仍然丢弃** ——
  靠 `await createDoubaoChatReply` 之后那句 `if (!liveRef.current) return`。
  理由：用户第一条抱怨的就是「断开后还在回复弹幕」，让它再念一条正好撞在枪口上；
  而已经出声的半句话被掐掉是另一种难受。两件事分开处理才对。
- 验证 `verify-disconnect-finish-speech.mjs`（9 项全 PASS）：把 `window.Audio` 换成桩 ——
  **只拦 `blob:` 开头的参数**（TTS 那条），`new Audio()` 原样交给真构造函数，免得弄坏 MusicProvider；
  桩的 `play()` 计数并 4s 后手动发 `onended`，`pause()` 计数。
  说到一半点断开 → `pauses` 保持 0、4s 后 `ended` 触发、之后 5s 没有第二条、历史里正好 1 条。
- **这个用例也做了反向验证**：把 `stopSpeaking()` 加回去再跑，`pauses` 立刻变 1、两项 FAIL，
  确认测的是真行为。

## 粒子加实物形状（水滴/绒毛/树叶/花朵/卡通人物/表情/雪花）

> **已按用户要求整版回滚（当天 02:48）** —— 组件改动、7 个 SVG、vendor 补丁全部移除，
> 下面的记录只作踩坑参考，代码不在库里。

- 需求：「粒子特效不要全是几何图形，加一下实物图」。做法是走 particles.js 的 `image` 形状 +
  本地 SVG（`public/particles/*.svg`，7 个，白色单色、只靠 `fill-opacity` / `stroke-opacity` /
  非零绕向挖洞表达明暗）。**没有**改 vendor 的绘制逻辑，也没有换成 png。
- **根因一（关键）**：vendor 里 `tmp` 是空对象，`createSvgImg` 里 `pJS.tmp.count_svg++` 把
  `undefined` 自增成 **NaN**，`draw()` 的 `count_svg >= N` 永远 false —— image 形状一个都画不出来，
  画布一直停在「still loading」。诊断脚本读出来 `countSvg: null` 就是 `JSON.stringify(NaN)`。
- **根因二**：那个门槛拿 `pJS.particles.number.value` 比，但 `densityAutoParticles()` 会按画布面积
  删粒子（840×828 时 44 → 35），实际 `array.length` 永远小于 `number.value`，门槛同样够不着。
- 于是给 `public/vendor/particles.js` 打了 **3 处本地补丁**（文件头写了补丁清单）：
  `tmp: { count_svg: 0 }`；`count_svg >= pJS.particles.array.length`；外加注释。
  **以后若重新 vendor 这个文件，这两处必须重新打**，否则实物粒子会静默变空白。
- 组件侧四处必改（`Atmosphere/index.tsx`）：
  · `sizeRandom?: boolean` 新字段 —— 库里半径是 `Math.random() * size`，一半图形小到认不出；
  · `opacity: 1` 且关掉 `opacityRandom` —— opacity 还要再乘强度（默认 0.55），写 0.6 实际 0.33；
  · `size` 要倒推：真实半径 = `size × 面板大小滑杆(初值 2.5)`，SVG 图形又只占画布一部分
    （水滴 .89 / 树叶 .68 / 绒球 .62），所以基准值只有 4～8。直接写 7/9/11 会变成 35～55px 大贴图；
  · `shape.image: { src, width: 100, height: 100 }` —— 宽高必须给，缺了 ratio 是 NaN。
- 路径必须是 `${import.meta.env.BASE_URL}particles/xxx.svg`：库靠 src **最后三个字符**判断 svg/png，
  末尾不能拼查询串。
- SVG 画法踩坑：① 同一形状里**不要**用多个 `<circle>` 叠（同色叠两次 alpha 更实，接缝发亮），
  要合并成一条 path 走 nonzero；② 眼睛/叶脉这种「洞」用**反向绕向**做，别用 `fill-rule="evenodd"`
  ——evenodd 会把头与身体的交叠也减掉，脖子上多一道黑线；③ 正着放的「尖头朝上 + 圆底」和水滴
  一模一样，树叶必须斜放 + 带叶柄才分得清；④ 绒球别用「实心球 + 放射短线」（看着像太阳/海胆），
  也别用振幅太小的鼓包（<1px 被抗锯齿抹平成正圆），最后用 16 瓣 / 半径 23～31 的连续起伏。
- 验证 `verify-particle-shapes.mjs`：把画布 1:1 裁 420×420 拼图 + 单独渲染 7 张 SVG 原图，
  两件事分开看（画得对不对 / 放进去多大）。`particle-zoom.mjs` 找第一颗粒子裁 90×90 放大 3 倍看细节。
- 验证 `verify-particle-final.mjs`（10 项全 PASS）：7 个预设都只有 1 个容器 1 张 canvas 且覆盖 >0.5%；
  反复切换后容器数仍是 1（没泄漏）；刷新后恢复成 `stage-particles-snowflake` 并重新画出来；
  浅色主题下正常。**注意 `addInitScript` 每次 reload 都会跑**，里面无条件 `localStorage.clear()`
