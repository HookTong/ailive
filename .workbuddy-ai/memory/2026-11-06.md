## 修「最近回复」卡片被拉高（高度失控）

- 现象：3 条回复各被撑成 ~210px 的高空卡片，提问和正文被顶到两端。
- 根因：`.history ul` 是 `display: grid` + `flex: 1 1 0`（拉满剩余高度），而 **grid 的 `align-content` 默认值是 `normal`，对 grid 容器表现为 `stretch`** —— 行数少时多余高度被平摊给每一行，行就长高了。`li` 自己也是 grid，同样把内部两行撑开，所以小字和正文之间空了一大块。
- 修法：`ul` 和 `li` 都加 `align-content: start`。行按内容高度排，空白留在列表底部（列表仍然吃掉剩余高度、内容多时自己滚，原设计不变）。
- 实测（1600×950，3 条回复）：每张卡 48px（原 210px），卡内小字与正文间距 2px，`ul` 高 283、内容 156，空白落在底部；1280×700 下卡仍是 48px、列表 140 内部滚动。
- `tsc -b --force` / `vite build` exit 0。

## 礼物 → 角色动作：价格列后加「触发角色动作」按钮 + 弹窗

- 弹窗里的选择只写进**草稿**（`draftMotions`），点「确定」才落到草稿表、抽屉再点完成才落 `localStorage`。取消/点遮罩都不改写已存的配置。
- 存储：`localStorage['ailive.gift-motions']`，形如 `{"小心心":"splash"}`。空串表示不触发，保存时**从表里删键**，不留无用条目。`setGiftMotions` 里也过滤一遍空值。
- 触发链路：`App.tsx` 里从 `douyinRoom.feed` 倒序找最新一条 `kind === 'gift'`，按 `giftMotions[item.text]` 取动作，`updateActiveCharacter({ activeMotion, motionNonce: motionNonce + 1 })`。
- 三个坑，都在这一步踩到了：
  1. **礼物可能在 `manifest` 加载完之前到达**（Live2D 模型加载约 2.8s）。effect 依赖里必须带 `manifest`，否则 `manifest?.motions[motion]` 为 undefined，第一个礼物直接丢掉且永不重试。
  2. **依赖带多了会重放**。`giftMotions` 一改（用户刚保存配置）effect 就重跑，会把上一条礼物再做一遍。用 `triggeredGiftRef` 记已处理的 `id` 挡住。类型是 `string | number | null`（`LiveFeedItem['id']` 是联合类型）。
  3. **同一个动作值没变，Live2D 不重播**。连送两个同款礼物时 `activeMotion` 前后都是 `splash`，`model.motion()` 不会被调用。加 `motionNonce` 计数器：值变了就重播，`Live2D` 的 `applyModelProps` 里 `motionReplay = (next.motionNonce ?? 0) !== entry.motionNonce`，和 `motionChanged` 取或。
- **`Modal` 必须放在 `Drawer` 外层**：抽屉内容区是 `overflow: auto`，嵌在里面的弹窗会被裁掉。`Modal` 用 `zIndex={40}` 压过 `Drawer` 的 31。
- 校验：
  - 14 行 14 个按钮；弹窗 `z-index: 40`、420×279、居中不被裁；下拉 9 项（不触发 + 8 个动作分组）。
  - 预置 `{小心心: splash, 跑车: bubble}`，1.2s / 4.5s / 7.8s 各来一个礼物 → 动作序列 `待机 → 鲸鱼喷水 → 吹泡泡糖 → 鲸鱼喷水`，第三次是同一动作重播，说明 `motionNonce` 生效。
  - 保存配置不重放：保存前「鲸鱼喷水」，保存后仍是「鲸鱼喷水」，`localStorage` 已更新成 `selfie`。
  - 取消链路：弹窗取消后已配置数不变、重开弹窗仍是原值、点遮罩只关弹窗、抽屉取消后 `localStorage` 保持 `{"小心心":"splash"}` 未被改写。

## 礼物动作改成「每个模型各配一个」

- 原来的 `giftMotions: Record<礼物, 动作名>` 只对当前角色有效，换模型后配置就失效。改成 `Record<礼物, Record<模型 id, 动作名>>`（`GiftMotionMap`），同一个礼物可以给每个模型各配一个动作，收到礼物时各做各的。
- 弹窗里不再是一个下拉，而是「一个模型一行」：模型名（当前角色带「当前」胶囊）+ 自己的动作下拉。当前角色排最前，其余按控制台顺序。这比「先选模型再选动作」少一次点击，也能一眼看全所有模型的配置。
- `App.tsx` 的触发从 `updateActiveCharacter` 改成遍历 `modelSources`、对每个模型 `updateCharacter(id, …)`。为此 `ModelContext` 加了 `updateCharacter(id, patch)`，`updateActiveCharacter` 变成它的一层包装。
- 舞台是同时渲染所有模型的，所以非当前角色也能被驱动 —— 实测：当前角色配 splash、副角色配 bubble，礼物到达后切到副角色，caption 是 `bubble`。
- **旧格式迁移**：早期只存一个动作名，不知道是给哪个模型配的。加载时归到通配键 `GIFT_MOTION_ANY_MODEL = '*'` 下，解析时 `entry[modelId] ?? entry['*']`，哪个模型有同名动作就跟着用；用户在弹窗里确认一次就把该礼物的通配键展开成具体模型（写回时丢掉 `*`）。模型 id 是 `whale-local` / `online:…`，不会和 `*` 撞。实测旧数据 `{"小心心":"splash"}` 仍能触发，保存后变成 `{"小心心":{"whale-local":"splash","online:…":"bubble"}}`。
- **又一个多模型才暴露的时序坑**：manifest 是并行加载的，先加载好的模型会把这条礼物「用掉」，后到的模型永远丢掉。加了 `pendingModelsRef` 记「这条礼物还有哪些模型没就绪」，effect 重跑时只补这几个，已经做过的不重放（否则 `motionNonce` 会让它们重播一遍）。用 `page.route` 把线上模型的 manifest 延迟 5s 验证：礼物落在空档里，当前角色立刻 `鲸鱼喷水`，副角色在 manifest 到位后补上 `bubble`。
- 下拉菜单是绝对定位、没有 portal，所以模型列表**不能加内部滚动** —— 祖先一旦 `overflow: auto` 菜单就被裁掉。模型多时让弹窗自然变高。
- 顺带发现：线上模型（从 model3 推导 manifest）的动作 label 就是分组名本身（`splash` / `bubble`），只有带 `manifest.json` 的模型才有中文 label。不是 bug。
- 校验：`tsc -b --force` / `vite build` exit 0；弹窗 1600 视口 460×311、420 视口 380×326 都在视口内，行内名字与下拉垂直居中，长模型名省略号截断、`title` 保留全文；保存不重放、取消不改写两条回归仍通过。

## 数字输入框：箭头只在聚焦时出现 + 右侧可配文字

- `Input` 的步进器从「常显、贴着右边缘飘着」改成「聚焦才出现、带分隔线的一条竖栏」：整块 `opacity: 0 / pointer-events: none`，`.wrap:focus-within` 时恢复。两个箭头之间也加一条分隔线，照系统数字框的样子。
- **平时不白占右内边距**：`.stepped` 不再写死 `padding-right`，而是聚焦时才给 30px，并加 `transition: padding-right .12s`。右对齐的数字是「滑过去」而不是跳一下。
- 新增 `addon?: ReactNode`：渲染成输入框右侧的独立方块（同高、6px 缝、`$bg-inset` 底 + `$border-input` 边、`mono(10px)`）。礼物单价的 `<em>元</em>` 换成 `addon="元"`，网格第三列 132px → 148px 补偿。
- **踩到的坑**：外壳 `.wrap` 用 `display: flex` 保证高度等于输入框，但 AI 配置里的 `.field > span { display: block }`（0,1,1）会把它压回 block —— 步进器用 `top/bottom` 贴边，外壳一旦变 block，行内元素底部那几像素基线间隙就露出来，箭头会超出输入框。修法不是加 `!important`，而是让 `.wrap > input { display: block }`：不管外壳是什么 display，外壳高度都严格等于输入框高度。
- 密码框的眼睛不受影响（`.wrap` 也改了，但眼睛是绝对定位居中）。
- 校验：未聚焦 `opacity 0 / pointer-events none / padding-right 8px`，聚焦后 `1 / auto / 30px`；点两次增加 0.1 → 0.12（step 0.01）；失焦回到 0/8px。1600 与 420 视口下输入框 112×32、元块 30×32、按钮 74×32，三者同顶同高。AI 配置的 lg 数字框外壳 36px、步进器 34px、上下各让 1px。

## 步进器改为「鼠标移入就显示」

- `.wrap:focus-within .stepper` 扩成 `.wrap:hover .stepper, .wrap:focus-within .stepper`；右内边距同理（`padding-right: 8px → 30px`），否则箭头会盖住右对齐的数字。

- 副作用：右对齐的数字在鼠标移入时会左滑 22px（和聚焦时同一段过渡）。如果觉得晃，把 `.stepped` 的 `padding-right` 固定成 30px 即可去掉滑动。

## 普通文本框加清除按钮（默认开，可 prop 关掉）

- `Input` 新增 `clearable?: boolean`，默认 `true`。只给「普通文本框」：密码框（眼睛）、数字框（步进器）已经占了右侧，`variant="bare"` 也不掺和。要关就 `clearable={false}`。
- 按钮只在**有内容**时渲染（看 `value`，组件全是受控的），显隐靠 `.wrap:hover` / `:focus-within` 切 `opacity` + `pointer-events`，和步进器同一套。右内边距同理：`.cleared` 平时 8px，悬停/聚焦 26px。
- **清空不能直接赋 `el.value`**：React 的 `_valueTracker` 会判成「值没变」，`onChange` 不触发、父组件的 state 不动。必须借 `HTMLInputElement.prototype` 上的原生 setter 写进去再补发 `input` 事件（`stepUp/stepDown` 走的是内部 setter，所以步进器不需要这招）。这样调用方的受控逻辑一行都不用改。
- 为了让按钮有定位锚点，普通文本框现在也包进 `.wrap` 了。检查过 10 处调用点：`.wrap` 的 `width: 100%` + 输入框 `display: block` 让宽度和包裹前一致；弹幕面板连接行（`display: flex` + 输入框 + 连接键）实测 242 = 196 + 6 + 40，无重叠。
- 踩到的探针坑：`row.querySelector('button')` 会先命中新加的清除键（它在 `.wrap` 里、DOM 更靠前），量出来 20px 像是把连接键挤扁了。要按 `aria-label !== '清除'` 过滤。
- 实测：有内容未悬停 `opacity 0 / pe none / pad 10px`；悬停 `1 / auto / 26px`；点清除后值清空、按钮消失（`hasBtn false`）、padding 回 10px，且只清当前这个框（同表单的模型名仍是原值）；空值框没有按钮。
- `tsc -b --force` / `vite build` exit 0。
