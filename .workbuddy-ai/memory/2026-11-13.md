## ~~舞台四块浮层支持小/中/大三档尺寸~~（已废弃）

- 需求：概览 / 礼物动作 / 弹幕 / 指令四张卡支持 3 种大小，用 `Segmented` 放在 `StageToolbar` 上。
- 实现：`Stage` 根节点 `.preview` 定义三个 CSS 变量，`data-overlay="sm|md|lg"` 切换；
  四张卡的 scss 只读变量，不再各自写死。

  | | 概览 `--overview-w` | 侧栏 `--overlay-w` | 高度上限 `--overlay-max-h` |

  | 小 | 460 | 232 | `min(52%, 420px)` |
  | 中 | 560 | 268 | `min(66%, 540px)` |
  | 大 | 680 | 312 | `min(78%, 660px)` |

## 顺手修的：拖动后的卡片切档会跑出舞台

- `useDragPosition` 加 ResizeObserver，容器宽度变化时把 `transform` 夹回父容器。
- **第一版写成了 `useEffect(..., [])`，完全没生效**：`GiftMotionCard` / `ChatCommandCard` 在没配内容时
  整块 `return null`，挂载那一刻 `ref.current` 是 null，effect 直接 return，之后再也不会跑。
  实测「拖到最右 → 切大档」溢出 44px（正好是 312-268）。
- 改成 `ensureResizeClamp()`，在 `handlePointerDown` 里懒绑；节点换了（条件渲染重挂）会重绑。
- 只认**宽度**变化：高度是内容驱动的（弹幕一多就长高），跟着夹的话每来一条弹幕卡片都往上跳一下。
- 复测：拖动后切大档，右边缘 1380 = 舞台边界，溢出 0px。

## 踩坑：Playwright 的 goto 一直超时

- `page.goto(..., { waitUntil: 'domcontentloaded' })` 90 秒超时，但 `page.title()` 能读到标题、`curl` 5ms 返回 200。
- 原因：`index.html` 里 `<link rel="stylesheet" href="https://fonts.googleapis.com/...">` 在国内网络挂起，
  样式表阻塞脚本执行 → `DOMContentLoaded` 迟迟不来。
- 解法：每个验证脚本开头加 `page.route('**://fonts.googleapis.com/**', r => r.abort())`，之后 commit 13ms、dcl 秒到。
  已记进 `VERIFY.md`。

## 最终方案：四块独立滑块 + `zoom` 等比缩放（取代上面两节）

- 用户澄清：「不是把卡片拉宽或拉长，而是等比例放大，里面的文字也得放大，因为在直播时用手机观看看不清卡片上面的字」。
  随后又改成「移除 toolbar 的 Segmented，改用 slider，四块各自调，放舞台控制台」。
- **只改宽度没用** —— 字还是 12px，手机上看不清。必须字号跟着变大。
- 用 `zoom` 而不是 `transform: scale()`：
  - `zoom` 是**布局级**缩放，文字按放大后的尺寸重新栅格化，**不糊**（实测 200% 截图文字锐利）；
    `transform: scale()` 会先按原分辨率绘制再放大，直播压缩下更容易糊。
  - `zoom` 连 padding / 圆角 / 图标 / 行高一起等比放大，一处生效，不用逐个改 px。
- 数据：`StageContext` 加 `OverlayScales = Record<'overview'|'giftMotion'|'chat'|'chatCommand', number>`，
  范围 `0.6 ~ 2`（`OVERLAY_SCALE_MIN/MAX`），默认全 1；落 `ailive.stage-console` 的 `overlayScales`，
  `resetStage()` 一起回到 1。
- 下发：`Stage` 从 `useStage()` 拿，在 `.preview` 上以内联样式设
  `--overlay-zoom-overview / -gift / -chat / -command`；四张卡各写 `zoom: var(--overlay-zoom-xxx, 1)`。
- UI：`StageControlPanel` 新增「浮层大小」块（滤镜之后、背景音乐之前），四个 `Slider`
  （`min 0.6 / max 2 / step 0.05`，右侧显示百分比）。块标题行 → 内容 = `$label-gap`，
  第一个滑块自带的 12px 上边距用 `.overlaySliders > :first-child { margin-top: 0 }` 压掉。

### `zoom` 踩到的坑（都修了）

1. **`transform: translate` 的 px 也被 zoom 乘了一次**。卡片被拖到最右（x=1080）再放大到 200%，
   位移变成 2160，直接飞出舞台（实测 right=2460）。
   修法：`useDragPosition` 里把所有位移和边界都换算成**布局坐标** ——
   `offsetLeft` / `offsetWidth` 在 zoom 下本来就是布局值，而 `stage.clientWidth` 是屏幕值，
   所以边界写成 `stage.clientWidth / zoom - offsetLeft - offsetWidth`，指针位移写 `(clientX - stageRect.left) / zoom`。
   `transform` 里存的是布局值，浏览器会再乘回 zoom，正好对上。
2. **`zoom` 不改布局尺寸，ResizeObserver 看不到它**。所以缩放变化时不会触发 clamp。
   修法：`useDragPosition` 加 `scale` 参数，`useEffect` 依赖它调一次 `clampToStage()`；四张卡各传自己那一路。
3. **zoom 元素里的百分比已经按缩放折算过**（Chromium 会把包含块先除以 zoom）。
   所以 `max-height: min(66%, 540px)` 在 200% 下视觉仍是 66%（实测 ratio 0.66），
   窄屏的 `calc(100% - 20px)` 也照旧写 —— 我一度多除了一次 zoom，卡片会缩得过小，已回滚。
4. 中途误判「断开」按钮被挤出卡片 —— 实际是截图压缩的错觉，`getBoundingClientRect` 显示按钮完整在卡片内。
   **别只看截图判断溢出，量 rect。**

### 追加：拖过的卡片置顶

- 需求：「这些卡片被点击拖动时应该把该卡片层级置顶」。
- 原来层级写死在 CSS：概览/礼物/指令 `z-index: 8`、弹幕 `9`。拖一张被压住的卡片时，
  手指按下的那半还在邻居底下。
- 做法：`useDragPosition` 里模块级 `let topZIndex = 9`，`pointerdown` 时 `setZIndex(++topZIndex)`，
  返回给调用方塞进 `style={{ transform, zIndex }}`。
  - **计数器必须模块级**：四张卡得共享同一个顺序，放各自的 state 会各数各的。
  - **松手不还原**：一放手就缩回邻居底下，等于白拖。
  - 赋值点在 `INTERACTIVE` 守卫之后 —— 点卡片里的按钮不算「拖这张卡」。
  - `resetToken` 变化时 `setZIndex(undefined)`，复位后回到 CSS 那套 8/9。
- 实测 `drag-zindex.mjs`：初始 8/9/8 → 拖概览 10 → 拖弹幕 11（概览仍 10）→ 点卡内按钮层级不变
  → 复位后内联清空、回 8/9。`overlap.mjs`：概览压住弹幕 268px，重叠区 `elementFromPoint` 归概览。
- `tsc -b --force` + `vite build` 通过。

### 追加：「全部」滑块改成单向（只向下写）

- 需求：「全部滑块 可以控制 单独滑块，单独滑块 不能控制 全部滑块」。
- 上一版是派生值（四块一致才显示数字，不一致显示「分别设置」并把滑块退到平均值）——
  等于单独滑块反过来控制了全部滑块。现在「全部」有自己的 `useState`：
  `initialUnified()` 只在挂载时从四块推一次（一致用那个值，不一致退平均值），之后独立。
- 联动方向：`handleAllScalesChange` 先 `setScaleAll(value)` 再逐个 `setOverlayScale`；
  单独滑块只写自己那一块，**完全不碰 `scaleAll`**。「分别设置」文案随之删掉。

  滑块自己的值不在那儿；不一起拉回，它还停在旧数值上，用户一碰就把四块拽回去。

  **存毫秒、面板按秒调**（存秒的话 provider 里还得再乘一次 1000，容易漏）。
  范围 `AI_THROTTLE_LIMITS` 一处定义，落盘校验和滑块共用。
- provider 删掉 `MIN_REPLY_INTERVAL_MS` / `CHAT_USER_COOLDOWN_MS` / `SAME_TEXT_WINDOW_MS` 三个常量，
  三处改读 `settingsRef.current.throttle.*`；`enqueue` / 泵都是 ref 读，不吃渲染时机。
- **出错退避改成 `max(ERROR_BACKOFF_MS, 间隔)`**：原来固定 15s，用户把间隔调到 60s 时
  反而让重试比正常间隔更快。
- UI：主播人设下面加「节流参数」分组（分隔线 + 右侧「越小回得越勤，token 花得越快」），
  三根滑块 1~60s / 0~120s（0 显示「不限」）/ 0~300s（0 显示「不去重」）。
- 实测：
  - `throttle.mjs`：默认 6s/6s/30s；改 3/0/15 保存后 storage 正确；重开读回 3/0/15。
  - `throttle2.mjs`：脏数据 `999999 / -5 / 'x'` → 夹成 60s / 不限 / 30s。
  - `throttle-behavior.mjs`（mock 直播流 + mock Ark）：12 条 1.2s 一条，**间隔 2s → 回 7 次、
    6s → 3 次、15s → 2 次**，实际间隔跟着走。注意 mock 脚本也要拦 Google Fonts，否则 goto 超时。
- `tsc -b --force` + `vite build` 通过。
