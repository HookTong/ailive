## 固定值不参与模糊匹配

- 规则定死：**模板里带 `$` 的才是变量**（走 `utils/matchName` 的模糊匹配）；关键字 / 限定词 / 修饰词是**固定值**，一字不差。
- 现状：`parseAction` 里 `keyword` / `qualifier` / `modifier` 本来就是 `!==` 精确比，但**写错一个字的固定值会掉进名字槽**（`[背景|固定的]` → `background`，payload `固定的`），再被 `findClosestMatch` 拿去和背景名模糊匹配 —— 这才是真正的漏洞。
- `actions.ts` 新增 `fixedValuesOf(keyword)`（这一族的固定写法）和 `closestFixedValue(keyword, value)`（只用来**报错**，不执行：允许「差不多」就分不清 `固定` 和 `固定式` 了）；`parseAction` 补一手**精确提升** —— 名字槽里写的正好是这一族的固定写法时改判成那条动作（`[外观|角色]清除` → `expressionClear`，`[背景]无背景` → `backgroundNone`）。
- `useChatCommand` 加 `fixedMismatch()`：**只在名字查不到之后**才问「这是不是固定值写错了」，避免挡住真叫这个名字的预设。命中就说「「固定的」不是背景名，固定写法要一字不差：无背景 / 固定 / 循环切换」。
- 说明文字那句改成「变量名称不用写全：记得个大概、多打几个字、错一个字都能对上；没带「$」的是**固定写法**，得一字不差」—— 一组对比，两处高亮（现在 6 处）。
- 校验：解析器矩阵 25 例（`固定的`/`固定式`/`循环`/`单曲` 都不命中固定动作、`[外观|角色]清除` 提升成功）；Playwright 9 项（报错文案、不改模式、精确命中、`[背景]幻想乡` 仍模糊、`[音乐|随机播放]` 精确、`完全不相干` 仍报「没有找到」+ 可选值、`[外观|鲸鱼]清除` 执行）；8 项 + 8 项原回归全绿，零 pageerror。
- 没动：`voice` 那族的固定值是空的（`fixedMismatch` 恒返回 null，只为统一形状留着）；播报仍是「粒子特效…」。

## 严格照模板：名字只认 `]` 后面

- 上一版为了让「固定值写进名字槽」也说得过去，给 `parseAction` 加了**精确提升**（`[外观|角色]清除` → `expressionClear`）。用户打回：**只有 `[外观|角色|清除]` 才能清除**，所有命令都要严格照模板。提升已删。
- 同时删掉 `match.name: 'payload-or-head1'`（`ActionMatch.name` 现在只有 `'payload'`）：名字只认方括号**后面**那段，`[背景|电影]` 不再是 `[背景]电影` 的别名。四条舞台动作（背景 / 特效 / 滤镜 / 音乐）跟着改成 `name: 'payload'`。
- 报错补一条分支：固定值**一字不差**却写错位置时（`[外观|角色]清除`、`[背景]无背景`），不执行也不模糊匹配，直接 `findFixedAction` 拿到那条动作的 `template` 递回去 ——「「清除」是固定写法，要按模板写：[外观|$角色名称|清除]」。写错一个字的（`[背景]固定的`）仍走 `closestFixedValue` 报固定写法清单。
- 代价（已告知用户）：`[背景|固定的]` 这种形状不对的现在**不是指令**，落回普通弹幕 / 自然语言路由，不再有「固定写法要一字不差」那句提示。
- 校验：解析器矩阵 28 例，每条命中都反查「head 段数 = 模板段数、名字在 `]` 后才有 payload」，形状不符 0；Playwright 6 项（`[背景|电影]` 完全不解析、`[背景]无背景` 只报模板、`[外观|鲸鱼]清除` 只报模板、`[外观|鲸鱼|清除]` 真清且只清一次、`[音乐]随机播放` 只报模板）+ 8 项 + 8 项原回归全绿，零 pageerror。

## 模板换新约定：方括号里全是固定值，外面全是变量

- 新格式 `[固定值|固定值]变量>变量`，多个变量用 `>` 隔开。`[外观]$角色名称>$外观名称`、`[外观|清除]$角色名称`、`[音色]$角色名称>$音色名称`。
- `ActionMatch` 收成 `{ keyword, qualifier? }` —— `modifier` / `head1` / `name` 全删，`[外观|角色|清除]` 变成 `[外观|清除]角色`。方括号最多 2 段。
- **模板改成生成**：`buildTemplate(spec)` = `[keyword|qualifier]` + `params.map(p => `$${p.label}名称`).join('>')`。`ACTION_SPECS` 里不再写 `template`，导出时 `map` 出来。`params` 同时是「变量顺序」和「tool 参数顺序」，三处终于只有一份。

- 面板说明第二句改成「**方括号里是固定写法**，要一字不差，斜杠表示任选一个；方括号外面是变量，多个用「>」隔开」，示例行 `[外观]DS 鲸鱼娘>love`；高亮回到 5 处。

## 指令写法的弹幕不再回落

- 新增 `data/actions.ts` 的 `looksLikeCommand(text)`：`[` 开头 + 有 `]` + 方括号第 1 段是认识的 keyword。`AiChatProvider` 的 feed 循环把它放在最前面，命中就 `continue` —— 解析成功但指令被关掉、在冷却里、形状不对，全都到此为止，不再交给 `useActionRoute` 也不 `enqueue`。

## 自然语言控制只作用于开启项

- 硬约束其实早就在三层挡着：① `enabledActionIds(chatCommands)` 只把开着的 id 传给 `routeAction`，`buildActionTools` 按它生成工具表；② 模型返回的调用再过一遍 `enabledSet.has(meta.id)`；③ 执行前按 `chatCommandsRef.current[action.id] !== false` 再滤一次（兜住 60s 缓存期间关掉的情况）。实测：关掉「背景切换」后工具表 22 → 21、`set_background` 不在里面，模型硬塞回来也不执行。
- 这次补的是**提示词层面**：状态快照按开关裁。一族全关就整个域不出现（`background` / `particles` / `filters` / `music` / `characters` / `voices`），只关了「背景切换」则保留 `current` / `mode`、去掉 `options`（预设清单只服务那条动作）。`can(...ids)` 是这一族里有没有开着的动作。
- 动机：关掉的东西还写在提示里，模型会看得见却调不动，容易回一句「好的，已经换成电影背景了」。

## 失败播报去掉可选值

- `useChatCommand` 里那个 `available(labels, limit)` 助手整个删掉：它给每条「没找到」后面接「，可选：A / B / C」或「等 N 个」。这条话是要念出来的，后面半句又长又听不清，还常盖住前一句。
- 现在失败只有一句：「没有找到「完全不相干」这个背景」（15 字）/「没有找到「不存在的特效」这个粒子特效」（18）/「「DS 鲸鱼娘」没有「不存在的外观」这个外观」（22）。
- 固定值那条也砍掉清单：`「固定的」不是背景名，固定写法要一字不差：固定 / 循环切换 / …` → `「固定的」不是背景名，固定写法要一字不差`。**保留**「「清除」是固定写法，要按模板写：`[外观|清除]$角色名称`」—— 那是唯一能让人知道正确写法的一句，不是可选项清单。
- 顺手删掉不再用的 `fixedValuesOf` 导入。
