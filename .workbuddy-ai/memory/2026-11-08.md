## 名牌遮挡角色：固定比例换成按 drawable 顶点量真实底边

用户发了一张三角色舞台截图：「有的名称标签遮挡了模型」—— 左边「阿虚」的名牌压在了手臂上，中间「DS 鲸鱼娘」的却离桌子老远。

根因是上一版用 `NAMEPLATE_BOTTOM_INSET = 0.08` 这个**固定比例**往上收。`getBounds()` 是几何包围盒、不含透明像素，而**每个模型画布底部的留白差得很远**：鲸鱼娘空出约 13%（名牌得往上收才贴脚），阿虚那种几乎贴底（再收 8% 就压到身上）。固定值两头不讨好 —— 收少了飘、收多了遮。

改成加载时量一次真实的内容底边：

```ts
type CoreModelWithDrawables = {
  getDrawableCount?: () => number
  getDrawableVertexPositions?: (index: number) => Float32Array | undefined
  getDrawableDynamicFlagIsVisible?: (index: number) => boolean
  getDrawableOpacity?: (index: number) => number
  getCanvasHeight?: () => number
}
```

遍历所有 drawable 的顶点取 `minY`（Cubism 模型坐标原点在画布中心、y 向上），`trim = (canvasHeight / 2 + minY) / canvasHeight` 就是底部留白占画布高度的比例，名牌放在 `1 - trim` 处。

**走过的弯路（重要，别再试）**：

1. 第一版用 `renderer.extract.pixels(model)` 读像素轮廓 —— **这条路是死的**。extract 按 `getLocalBounds()` 建离屏纹理，而 Live2D 这个值返回的是**画布原始尺寸 4068×4068**（不是缩放后的 600×600），纹理 66MB，扫一遍 6600 万像素要好几秒，主线程直接卡住。而且 extract 内部会把对象临时挂到空父级再渲染，模型还在舞台坐标上，内容整个画在纹理外面 —— 读回来是空图，静悄悄地兜底成 0，看不出哪里错了。
2. 第二版没过滤 drawable 的可见性 —— 269 个里只有 93 个真正显示，剩下的是遮罩/已移出画面的，`minY` 跑到 -0.6577（画布底边是 -0.5），算出来的 trim 是负的。加 `getDrawableDynamicFlagIsVisible` + `getDrawableOpacity > 0.01` 之后 `minY = -0.3708`，trim = 0.129，和视觉估计对上了。
3. 顶点在模型 update 之前全是 0，`minY = maxY = 0` → trim = 0.5，名牌会被推到角色腰上。加一道「`highest - lowest < 0.01` 就当没量到」的检查，退回贴包围盒底边。

**兜底原则**：拿不到数据（Cubism 2.1 没有这些方法、顶点没准备好）就返回 0 = 贴包围盒底边。**宁可飘一点，也不能压到角色身上**。

实测（`tsc -b --force` 通过）：

| 场景 | 改前（inset 0.08） | 改后（顶点测量） |
| --- | --- | --- |
| 鲸鱼娘默认 60% | top 625，离桌子约 210px | top 612，紧贴桌子下方 4px |
| 模型拉满 | — | top 690，名牌底边 722（舞台高 876） |
| 模型最小 | — | top 522 |
| 双角色 | — | 两块名牌各贴各的模型，隐藏模型时一起隐藏 |

## 气泡「一进来偏小、切模型才变大」

用户：「页面一进来直接选气泡显示的常显，气泡显得很小，当我一切换模型气泡又会自动变大一些」。

**根因**：`--bubble-scale` 用 `bubbleScalesRef` 这个 Map 缓存「上次写进去的值」，**而气泡和名牌共用同一份缓存**。

时间线：
1. 模型加载完成 → 名牌挂载（气泡还没有，`speechText` 为空）→ `updateOverlays` 算出 `overlayScale`，写进 `bubbleScalesRef`，但因为 `bubble` 是 undefined，只把变量写给了名牌
2. 用户点「常显」→ 气泡挂载 → ref 回调只 `set(bubbleRefs)`，没碰缓存
3. 下一帧 `updateOverlays`：`previousScale` 有值且等于 `overlayScale` → **判定「没变化」跳过写入**
4. 气泡于是停在 CSS 里的 `--bubble-scale: 1`。模型真实缩放是 1.2 时就显得偏小；切换模型后 `bounds` 变了、值对不上，才终于写进去 —— 就是用户看到的「切一下又变大」

**改法**：不再维护 Map，直接和元素上的实际值比：

```ts
const scaleValue = overlayScale.toFixed(3)
if (bubble.style.getPropertyValue('--bubble-scale') !== scaleValue) {
  bubble.style.setProperty('--bubble-scale', scaleValue)
}
```

行内样式的 `getPropertyValue` 不触发重排，每 4 帧读一次可以忽略。`bubbleScalesRef` 整个删掉（连同 cleanup 和 ref 回调里的清理）。名牌同理，`nameplateSizesRef` 的失效改挂在「`--bubble-scale` 真的变了」这个分支里。

实测（1680×1000）：

| 操作 | 改前 | 改后 |
| --- | --- | --- |
| 刚切「常显」 | `--bubble-scale: 1`（CSS 默认，没写入） | 0.963 ✓ |
| 切到另一个角色 | 0.963 | 0.963 |
| 模型 60% / 95% / 20% | — | 0.963 / 1.450 / 0.700（气泡），名牌 0.963 / 1.2（clamp）/ 0.9（clamp） |

名牌位置回归无变化（612 / 690 / 522）。

## 说话气泡放大一倍

用户：「这个气泡框默认放大一倍」。

`.bubble` 里的基准值整体 ×2，`--bubble-scale` 的换算方式没动（那是跟着模型大小走的）：

| 属性 | 改前 | 改后 |
| --- | --- | --- |
| `font-size` | `calc(11px * scale)` | `calc(22px * scale)` |
| `padding` | `calc(9px) calc(12px)` | `calc(18px) calc(24px)` |
| `max-width` | `calc(220px * scale)` | `min(calc(440px * scale), 86%)` |
| `border-radius` | `calc(12px * scale)` | `calc(24px * scale)` |
| 尾巴 `bottom` / 宽高 | `-7px` / `12px` | `-14px` / `24px` |
| `box-shadow` | `0 8px 20px` | `0 14px 32px` |

**`max-width` 后面那道 `86%` 是必须的**：440px 在窄窗口下会顶到舞台两边被 `overflow: hidden` 裁掉。百分比相对的是 `.live2d`（整块舞台），不是视口。

实测：1680×1000 下气泡 252×68、字号 21.19px（scale 0.963）；模型拉满 379×102、顶部 101 没出界；1180×820 窄视口 184×50、字号 15.4px（scale 被夹到下限 0.7），左右都没溢出。

**副作用**：气泡变宽后更容易和舞台浮层（礼物榜、弹幕指令卡）撞上 —— 截图里「礼物榜」就盖住了气泡左半。浮层本来就能拖走 / 隐藏，这次没处理自动避让。

## 弹幕指令的变量改成模糊匹配

用户：「弹幕指令的这些变量的匹配逻辑改成按相似度或者使用某种算法来计算关联性来匹配吧，因为用户可能不知道具体的值」。

**新建 `src/utils/matchName.ts`**，三件套：
- `normalizeName`：NFKC（全角转半角）+ 去空白/标点/符号 + 小写。`ＬＯＦＩ  P1` / `lofi p1` / `Lofi-P1` 归一化后都是 `lofip1`。

## 气泡遮挡模型（按包围盒顶边固定 3% 的老毛病）

用户：「为什么有的模型上面的气泡框会遮挡模型」+ 双角色截图（左边鲸鱼娘的气泡飘在头顶上方老远，右边白月光的尾巴已经插进头发里）。

**根因和名牌一模一样**：`BUBBLE_TOP_OFFSET = 0.03` 把气泡底边放在「包围盒顶边往下 3%」，而画布上方那圈透明留白**每个模型不一样**。留白多的（鲸鱼娘 topTrim 0.086）3% 还在头顶以上 → 飘着；留白少的（头发顶到画布上沿，topTrim ≈ 0.01）3% 已经在头发里 → 气泡压头。

**改法**：把 `measureBottomTrim` 扩成 `measureSilhouette`，一次遍历同时返回 `topTrim = (canvasHeight/2 - maxY) / canvasHeight` 和 `bottomTrim = (canvasHeight/2 + minY) / canvasHeight`；`ModelEntry` 多存一个 `topTrim`，气泡改按 `bounds.y + bounds.height * topTrim` 定位。

**尾巴要单独让位**：气泡是按底边定位的（`translate(-50%, -100%)`），而尾巴菱形还往下伸 13.7px（18px 方块转 45°、`bottom: -10px`：中心在底边下 1px，下尖再 12.73px）。所以 `top = 内容顶边 − 13.7 × scale − 4`。这个常数写死在 `BUBBLE_TAIL_DROP`，SCSS 里尾巴尺寸一改就得跟着改，两边注释互相指了一下。**别图省事只按底边放**——那样尾巴会插进头发，正是用户抱怨的那一幕。

顶部还要 `Math.max(0, …)` 夹一下：头顶顶到舞台上沿时气泡会被 `.preview { overflow: hidden }` 裁掉，宁可盖一点头发也得让字看得见。

**实测**（1680×900，本地鲸鱼娘）：`topTrim 0.086 / bottomTrim 0.129 / bounds.y 237.6 / height 362.88`，气泡 `top = 249.9`（= 268.8 − 14.9 − 4），尾巴尖离头顶 4px，截图里正好悬在女仆头饰上方。旧公式对这个模型给的是 248.5（尾巴尖离头顶 5.4px，纯属凑巧），对 topTrim≈0 的模型则是尾巴+气泡底部一起压在头发上。

## 气泡常显 / 名牌显示 加说明图标
