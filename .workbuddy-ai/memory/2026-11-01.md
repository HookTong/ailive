## dy-live：抖音直播间监听抽离

从 `cvv-cat/Douyin_Spider` 抽出 `dy_live` 部分，重建为独立项目 `E:/GitHub/ailive/dy-live/`。

关键决策：
- **弃用 PyExecJS**，改为常驻 Node 签名进程（`sign/signer.js`），行分隔 JSON 通信。原因：PyExecJS 每次 call 都 fork Node（~80ms），且签名 JS 里的 `console.log` 会污染 PyExecJS 的 JSON 解析。Node 侧 stub console 后通过独立协议返回。
- 签名 JS 在 Node `vm` 沙箱加载，需补 `global` / `performance` / `crypto.webcrypto`；`dy_ab.js` 只需 `jsrsasign` 一个 npm 依赖（`canvas`/`jsdom`/`sdenv` 都不需要）。
- 去掉上游的 `verify=False`、修正 UA 与 `sec-ch-ua` 指纹矛盾（统一 Chrome 138）、重连改指数退避且先查开播状态。

实测结论（重要）：
- 未登录 cookie 也能成功解析直播间页面，拿到 room_id / user_unique_id / room_status。
- `room_status`：2=直播中，4=未开播。
- **未开播房间调 `/webcast/im/fetch/` 返回 HTTP 200 + 空 body**，不是错误码，所以必须先查 room_status。
- `live.douyin.com/webcast/feed/` 这类 JSON 接口对 `requests` 直接返 444（TLS 指纹识别），但直播间 HTML 页面不拦。要扩接口需换 `curl_cffi`。

待办：拿一个正在直播的房间号做端到端 WS 验证（弹幕/礼物事件）。

## 端到端验证通过（23:40）

用用户提供的登录 cookie，房间 660292215268（room_id 7703188128085216000）跑通实时监听，弹幕/礼物/进场/关注/点赞/在线人数全部正常。

过程中发现两个**致命但不报错**的坑（上游代码都踩了）：
1. `/webcast/im/fetch/` **不能带 a_bogus**：带上返回 200 + 空 body + content-type: application/json（静默拒绝）；不带才返回 266KB protobuf。上游的 a_bogus 对该接口已失效。已在 `api.py` 改成「先不带、失败再带」的兜底。
2. `PushFrame.payloadEncoding` 值是 `'pb'`，但 payload 实际是 gzip（魔数 1f8b）。上游按 `== 'gzip'` 判断，永远解不开，报 `Wire format was corrupt`。已改成按魔数判断。

其他：csrf token（x-secsdk-csrf-token）能正常拿到；未登录 cookie 也能解析页面但成功率低；礼物消息的 toUser 常为空。

## 坑：舞台浮层无法输入

`.preview` 内有全屏透明拖拽层 `.model-interaction-layer`（position:absolute; inset:0; z-index:6），会盖住同 z-index 的新浮层。加浮层时必须：
1. z-index 设 9（高于拖拽层，`.stage-info-cards` 用的是 8）。
2. `App.tsx` 的 `handleStagePointerDown` 里把新浮层类名加进 `closest('.stage-info-cards, .live-chat-panel')` 的排除列表，否则 setPointerCapture + preventDefault 会让 input 失焦。

浏览器自动化（agent-browser）在此环境 open 会 SIGTERM 无输出，UI 只能靠用户验证。
